# 利润宝扫描财报识别修复实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让利润宝可靠识别 2022—2024 文本型及扫描型审计报告，提供可核对的三年核心数据，并确保 AI 只分析已确认数据。

**Architecture:** 保留 `core/parser.py` 的通用格式解析，在独立扫描财报模块中完成年度识别、目标页定位、坐标化 OCR、核心科目候选提取与跨年校验。Web 会话保存识别结果和人工修正，前端只展示结构化数据表，不传输或显示 PDF 原图。

**Tech Stack:** Python 3.13、FastAPI、RapidOCR、pypdfium2、pdfplumber、SQLite、React、TypeScript、Vite、pytest、Playwright。

## Global Constraints

- 新增文件名必须包含 `WB-CO-TR` 和精确到秒的时间戳。
- 验收统一使用项目 `.venv/bin/python`，不得使用系统 Python 伪造结果。
- PDF 可以在后端内部渲染供 OCR 使用，但接口和前端不得返回或显示原图。
- 缺失值必须为 `null`，不得默认填零。
- 低置信或冲突数据未经人工确认不得进入 AI。
- AI 未配置或调用失败时，离线识别、校验、修正和持久化必须继续工作。
- 增值税税负率必须标注“估算值（基于税金及附加反推）”。
- 不新增项目依赖，不改变 Excel、CSV、Word、PPT 的既有导入契约。
- 未经用户明确授权不得执行 `git commit` 或 `git push`。

    for source in (text, os.path.basename(path)):
