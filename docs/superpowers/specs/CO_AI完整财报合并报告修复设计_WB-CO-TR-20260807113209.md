# 利润宝 AI 完整财报合并报告修复设计

> 日期：2026-08-07 11:32:09  
> 状态：用户已确认设计方向，待书面复核  
> 回归样本：`web_backend/workspaces/2022年审计报告.pdf`、`2023年审计报告.pdf`、`2024年审计报告.pdf`

## 1. 结论与问题边界

本次只修复“导入三份审计报告后，AI 合并报告读取不完整或内容错误”的问题，不增加多会话、客户档案或通用文档管理功能。

当前错误可能由两条链路共同造成：

1. 当前 SQLite 会话是固定 `id=1` 的单会话，载入示例或再次导入会替换当前数据；
2. PDF 送入 AI 前已被本地截短，换成长上下文模型也无法读取未被采集的页面。

本设计以第二条为主要修复对象，同时增加报告身份校验，避免会话数据与报告标题不一致时保存错误报告。

## 2. 已确认事实

- 三份真实报告分别为 30、43、49 页，共 122 页。
- 当前 PDF 预览最多采集前 20 页。
- 扫描页 OCR 最多处理前 12 页。
- 每页文本层或 OCR 文本最多保留前 600 个字符。
- 单份报告 AI 提炼输出上限为 800 tokens，最终合并上限为 2500 tokens。
- AI 调用层只读取返回正文，没有检查 `finish_reason=length`。
- `summarize_years_for_markdown` 接收了确定性结构化摘要参数，但当前没有实际使用。
- 用户选择准确优先，允许完整处理约 3—10 分钟。

## 3. 目标与非目标

### 3.1 目标

- 完整读取三份 PDF 的全部 122 页，不因预览限制丢失后半部分。
- 按文件、年份和页码分段识别，生成 2022/2023/2024 跨年关键指标与分析报告。
- 使用 `deepseek-v4-flash`，保持官方 OpenAI 兼容 Chat Completions 接口。
- 发现输入缺页、模型输出截断、企业或年份不一致时停止保存，并返回明确错误。
- 使用现有确定性财务指标校验 AI 提取值，降低金额串列和年份串错风险。
- 前端显示可理解的处理进度，不让 3—10 分钟任务表现为页面卡死。

### 3.2 非目标

- 不复刻或重新输出整份审计报告正文。
- 不增加多客户、多会话或历史版本体系。
- 不改变 Excel、CSV、Word、PPT 的现有导入流程。
- 不把完整 OCR 文本返回前端，也不传输 PDF 原图给文本模型。
- 不改变项目既有税务指标口径与合规限制。

## 4. 方案选择

采用“完整 OCR + 分段提取 + 确定性校验 + 最终合并”。

不采用一次性提交全部文本：即使模型上下文足够，一次性请求仍可能忽略部分年份，且失败后难以定位具体文件和页段。

不采用仅识别财务报表目标页：该方式更快，但可能漏掉审计意见、重大事项及影响分析结论的附注，不符合用户要求的“完整读取所有页面”。

## 5. 总体数据流

```text
三份 PDF
  → 建立文件清单并记录总页数
  → 逐页提取文本层；无可用文本层时执行 OCR
  → 每页保存文件名、报告年度、物理页码、提取方式和完整文本
  → 按单份报告分段，逐段提取关键事实
  → 合并为每年度结构化结果
  → 与现有确定性指标交叉校验
  → 合并生成跨年报告
  → 检查企业、年份、页数覆盖与模型停止原因
  → 校验通过后显示并保存
```

预览通道和 AI 读取通道必须分离：预览仍可限制页数和字符数；后台 AI 通道不得复用预览用的 `notes` 截短结果。

## 6. 完整文档提取

新增独立的完整 PDF 文本提取接口或内部函数，职责仅为向后台分析提供完整、可追溯的逐页文本。

逐页记录至少包含：

- 源文件名；
- 推断报告年度；
- PDF 物理页码和总页数；
- 提取方式：文本层或 OCR；
- 完整提取文本；
- 空白页或识别失败状态。

要求：

- 遍历全部页面，不使用 `_PDF_PREVIEW_MAX_PAGES` 或 `_OCR_MAX_PAGES`；
- 不使用每页 600 字符限制；
- 有可靠文本层时优先使用文本层，无可靠文本层时执行 OCR；
- 单页识别失败不得静默跳过，必须记录失败页码；
- 任一文件存在未处理页面时，整体状态为“不完整”，不得宣称已完整读取；
- 完整文本只保存在本机后台和 SQLite，不进入浏览器响应。

为避免每次重新生成都重复 OCR，完整逐页结果按文件指纹缓存。文件内容变化时缓存失效。

## 7. 分段策略与 AI 提取

每份报告独立分段，不得跨文件混合。分段以完整页面为边界，单段包含连续页，并附带固定元数据：企业、文件名、年度、页码范围和总页数。

第一阶段逐段提取：

- 财务关键指标及原始金额；
- 审计意见；
- 经营趋势和重大异常；
- 影响跨年分析的重要附注；
- 每条事实的来源页码。

第一阶段使用结构化 JSON 输出。无法识别的字段保持空值，不得填零或猜测。

第二阶段按单份报告合并所有分段，形成年度结构化结果。合并时检查页码覆盖，确认从第 1 页到最后一页均已处理或有显式失败记录。

第三阶段将三个年度结构化结果与程序生成的确定性指标共同交给模型，生成最终跨年 Markdown 报告。

## 8. 确定性校验与事实优先级

`core.finance` 基于已解析 `FinancialData` 生成的指标是关键数字的校验锚点。AI 不得无条件覆盖确定性结果。

优先级如下：

1. 可追溯的结构化解析值及现有确定性计算；
2. 带来源页码、且通过跨段一致性检查的 AI 提取值；
3. 仅存在于文字附注中的定性信息。

同一指标不一致时：

- 最终报告采用确定性值；
- 同时标注“AI 提取与结构化指标不一致，建议核对来源页”；
- 保存冲突项、双方数值和来源页码，不静默选择 AI 数字。

增值税税负率继续使用项目既定估算口径，并显著标注“估算值（基于税金及附加反推）”。

## 9. DeepSeek V4 Flash 接入

- Base URL 默认提示为 `https://api.deepseek.com`；
- 模型默认提示和文档更新为 `deepseek-v4-flash`；
- 仍允许用户显式配置兼容模型，但报告生成时记录实际模型名称；
- 不把“模型上下文足够”当作取消分段的理由；
- 输出上限按任务配置，分段提取与最终报告分别设置，不沿用当前 800/2500 的硬编码；
- AI 引擎返回正文的同时必须暴露 `finish_reason` 和用量信息。

当 `finish_reason=length` 时，当前结果视为不完整。结构化提取优先缩小分段重试；最终 Markdown 可带上一段末尾上下文续写，完成后再做结构完整性校验。达到有限重试次数仍失败时返回错误，不保存半截报告。

## 10. 报告身份与完整性校验

最终保存前必须全部满足：

- 企业名称与当前会话一致；
- 包含 2022、2023、2024 三个年度；
- 三份文件的页面覆盖分别达到 30/30、43/43、49/49，或与本次实际文件页数一致；
- 每个年度至少包含营业收入、营业成本、利润总额或净利润的明确状态；
- 报告包含数据来源及缺失/冲突说明；
- 模型所有阶段均未以 `length` 或异常资源状态结束；
- 报告中的增值税税负率带估算口径说明。

若当前会话企业或年份与待生成报告不一致，接口应拒绝生成并提示重新导入正确文件。该校验防止示例数据或其他导入覆盖后继续生成错误报告，但本次不引入多会话机制。

## 11. 进度、错误与恢复

后台任务至少暴露以下阶段：

1. 正在读取文件；
2. 正在识别某文件第 N/总页数页；
3. 正在提取某文件第 N/总分段段；
4. 正在校验年度指标；
5. 正在生成跨年报告；
6. 正在执行完整性检查；
7. 完成或失败。

前端展示阶段、文件名和进度数字。用户切换页面后任务继续运行，重新进入总览时可恢复当前进度。

错误必须包含可操作信息，例如：识别失败的文件和页码、模型截断的阶段、缺失的年度或身份不一致。失败任务保留已完成的本地 OCR 缓存，以便重试，但不得写入正式报告记录。

## 12. 会话覆盖的最小保护

本次不改成多会话，只增加与本问题直接相关的保护：

- 自动化测试使用隔离的临时数据库，不得读写正式 `app.db`；
- 载入示例数据后，报告标题和身份校验必须以当前示例会话为准；
- 生成云南艺康报告前，若当前会话不是云南艺康 2022/2023/2024，则明确拒绝，不生成看似成功的错误报告；
- 真实文件重新导入仍按现有单会话规则替换当前数据。

## 13. 测试与验收

### 13.1 单元测试

- 完整提取不受预览页数及 600 字符限制；
- 文本层页与扫描页选择正确的提取方式；
- 分段不跨文件，页码连续且没有重复或遗漏；
- JSON 提取缺失字段保持空值；
- `finish_reason=length` 触发重试且不保存结果；
- 确定性值与 AI 值冲突时采用确定性值并保留冲突说明；
- 企业、年份和页面覆盖校验能够阻止错误报告。

### 13.2 API 与前端测试

- 长任务可查询进度，页面切换后状态可恢复；
- 失败响应包含具体文件、页码或阶段；
- 未通过完整性校验的报告不进入报告记录；
- 正式数据库不会被测试样例覆盖；
- 设置页默认提示使用 `deepseek-v4-flash`。

### 13.3 真实样本验收

使用项目内三份云南艺康报告执行一次完整流程：

1. 页面覆盖为 30/30、43/43、49/49；
2. 最终标题和正文企业名称正确；
3. 报告覆盖 2022、2023、2024；
4. 营业收入等核心数字与人工核对基准一致；
5. 报告包含趋势、异常、审计意见或重要事项；
6. 不出现半句话、缺尾部章节或未闭合 Markdown 表格；
7. 刷新页面后仍可查看已完成报告；
8. 再次生成能复用 OCR 缓存，并仍通过完整性校验。

## 14. 安全与合规

- 财务文件、完整 OCR 文本和中间结果只保存在本机；
- 只有用户已配置 AI 时才向其指定接口发送文本；
- 不记录或输出 API Key；
- AI 调用失败必须保留本地数据并允许重试；
- 所有报告继续遵守项目合规表述及既定财税计算口径。

## 15. 完成定义

只有当真实三份报告的全部页面都被处理、三个年度核心指标通过校验、最终报告完整且身份正确，并且相关自动化测试通过时，才算修复完成。单纯更换模型、扩大 token 参数或让接口返回 200 均不视为完成。
