## 一、产品全景与定位

### 1.1 产品一句话

面向**财税/代账机构**的本地桌面应用：导入企业近三年财报与科目余额表 → 按行业对标做税负率与成本费用结构诊断 → **多轮 AI 互动**（每轮给 3 个选项）→ 生成第二稿（含环比同比、增值比例与幅度、操作细节）→ 双方确认或落地性 >95% 时输出**完整方案**，并可一键导出 Word/PDF 报告与可运行的**成本优化测算模型**。

### 1.2 核心价值主张

| 维度 | 描述 |
|------|------|
| **标准化** | 财报诊断 + 成本优化建议标准化、可复用，降低对资深顾问的依赖 |
| **互动化** | 多轮互动把客户战略意图纳入方案，提升方案可信度与落地率 |
| **合规化** | 所有优化建议锚定合法税务筹划范畴，数据本地处理契合合规要求 |
| **可交付** | 产出物（报告 + 测算模型）可直接用于客户沟通与逐月跟踪 |
| **离线可用** | 大模型为可选项，未配置时由内置规则引擎兜底，离线也能跑通完整闭环 |

### 1.3 设计哲学

```
全部计算为确定性数学，可逐笔由原始报表反算复核
AI 交互为可选项，未配置时规则引擎兜底
数据不出本机，契合代账机构数据合规要求
```

### 1.4 成功指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 单客户诊断耗时 | 从导入到出方案 | ≤ 5 分钟（MVP 已验证） |
| 方案落地率 | 客户确认执行/实际采纳 | ≥ 60% |
| 可节税测算准确度 | 估算 vs 实际申报差异 | ±15% 内 |
| 报告一次通过率 | 客户无重大修改退回 | ≥ 80% |
| 离线可用率 | 无网络下完整闭环通过 | 100% |

## 二、用户角色与场景

### 2.1 用户角色矩阵

| 角色 | 核心诉求 | 使用频率 | 技术能力 |
|------|---------|---------|---------|
| **代账顾问**（主力用户） | 快速产出专业诊断，提升服务效率与质量 | 日常高频 | 中等（会操作 Excel） |
| **机构负责人**（管理者） | 统一交付标准，跟踪方案落地，沉淀知识资产 | 周/月 | 中等 |
| **企业客户**（间接用户） | 看到直观结论与节税测算，辅助决策 | 低频（每次合作） | 低 |
| **超级管理员/IT**（规划角色） | 行业基准校准、模板自定义、系统维护 | 偶尔 | 高 |

### 2.2 核心用户故事

| 编号 | 角色 | 用户故事 |
|------|------|---------|
| US-1 | 代账顾问 | 导入客户财报后自动得到税负率与成本结构对标诊断，以便快速定位优化空间 |
| US-2 | 代账顾问 | 系统就每条发现给出 3 个可量化选项，以便向客户清晰解释利弊 |
| US-3 | 代账顾问 | 输入客户战略意图后方案能迭代，以便方案贴合客户实际 |
| US-4 | 机构负责人 | 导出标准化 Word/PDF 报告与 Excel 测算模型，以便统一交付与跟踪 |
| US-5 | 企业客户 | 看到"该有没的/可有可没有"的直观结论与节税测算，以便决策 |
| US-6 | 代账顾问 | 未配置 AI 也能完成完整诊断闭环，以便在客户现场无网络时也能使用 |
| US-7 | 机构负责人 | 校准行业基准，以便诊断对标更贴合机构服务的企业群体 |

### 3.2 功能清单（EARS 规范）

#### F1 数据导入（Ubiquitous / Event-driven）

| 需求类型 | 需求描述 | 状态 |
|---------|---------|------|
| Ubiquitous | 支持导入 Excel(.xlsx/.xls) 与 CSV 格式财报数据 | ✅ 已实现 |
| Event-driven | 用户选择一个含"利润表/资产负债表/科目余额表"三 Sheet 的 Excel 时自动识别解析 | ✅ 已实现 |
| Event-driven | 用户分别导入三个文件时合并为统一财务数据集 | ✅ 已实现 |
| Unwanted | 文件无法解析或识别不到年份列时，提示"请检查报表模板"并中止 | ✅ 已实现 |
| Ubiquitous | 同义词词典归并金蝶/用友等科目名称差异 | ✅ 已实现 |
| State-driven | 导入完成后状态栏显示"企业名 / 行业 / 期间" | ✅ 已实现 |
| Optional | PDF 扫描件提示"暂不支持 OCR，请导出 Excel" | 📋 规划 |

#### F2 综合分析（税负率与成本结构）

| 需求类型 | 需求描述 | 状态 |
|---------|---------|------|
| Ubiquitous | 基于近三年数据计算：增值税税负率、所得税税负率、综合税负率、毛利率、各项费用率、期间费用率、净利率 | ✅ 已实现 |
| Event-driven | 点击"开始诊断"时渲染趋势图与结构图 | ✅ 已实现 |
| Ubiquitous | 增值税税负率标注为"估算值（基于税金及附加反推）" | ✅ 已实现 |
| Unwanted | 年营业收入为 0 时比率置 0 并标注"基数缺失" | ✅ 已实现 |
| State-driven | 税负率展示叠加行业合理区间对标参考线 | ✅ 已实现 |

#### F3 第一轮诊断（初稿建议）

| 需求类型 | 需求描述 | 状态 |
|---------|---------|------|
| Event-driven | 分析完成后，按严重度（高/中/低）排序生成诊断发现 | ✅ 已实现 |
| Ubiquitous | 每条发现含：事实、对标情况、初稿建议三类信息 | ✅ 已实现 |
| Unwanted | 增值税税负率低于行业下限且收入正常，标记为"真实性关注（高风险）" | ✅ 已实现 |
| Ubiquitous | 识别"该有没的"与"可有可没有/应控" | ✅ 已实现 |
| Ubiquitous | 所有建议必须合法税务筹划，固化合规声明 | ✅ 已实现 |
| Optional | 机构已校准行业基准时使用校准区间对标 | 📋 规划 |

#### F4 多轮互动

| 需求类型 | 需求描述 | 状态 |
|---------|---------|------|
| Event-driven | 针对当前未决发现给出 A/B/C 三个选项（含影响测算与落地可行性） | ✅ 已实现 |
| Event-driven | 用户选择某选项后记录选择并推进到下一条未决发现 | ✅ 已实现 |
| Event-driven | 用户补充战略意图时记录并据此继续给出选项 | ✅ 已实现 |
| State-driven | 仍有未决发现时持续进入下一轮，直到全部处理完或用户请求生成方案 | ✅ 已实现 |
| Optional | 配置大模型 key 后用 AI 增强自然语言解释 | ✅ 已实现 |
| Unwanted | 用户输入与财务优化无关内容时引导回主题 | ✅ 已实现 |

#### F5 第二稿方案

| 需求类型 | 需求描述 | 状态 |
|---------|---------|------|
| Event-driven | 全部发现处理完成或用户请求时生成第二稿 | ✅ 已实现 |
| Ubiquitous | 每条决策给出：历史环比同比、后续增值比例与幅度、操作细节、注意事项 | ✅ 已实现 |
| Ubiquitous | 增值比例与幅度以"当前值→目标值→变动幅度→预计节税"结构呈现 | ✅ 已实现 |

### 4.3 交互详细说明

**导入阶段**
- 拖拽或点击选择文件（.xlsx / .xls / .csv）
- 自动识别三表合一/分文件
- 同义词归并后展示"匹配成功 xx 项 / 未匹配 yy 项"（未匹配项允许手动映射）
- 状态栏更新：企业名 / 行业 / 期间

**诊断阶段**
- 点击"开始诊断"后进度条 + 处理中动画
- 完成后左区展示：指标卡片（每个卡片含数值 + 行业参考线 + 趋势标记↑↓→）
- 诊断发现列表按严重度排序，高严重度红色标注

**互动阶段**
- 当前发现显示在最上方
- A/B/C 三个选项以卡片按钮呈现（每个选项含标题 + 简要影响说明）
- 选择后动画过渡到下一条发现
- 自由输入框在底部，提交后作为上下文注入下一轮选项生成
- 右侧对话记录持续更新

**第二稿与完成**
- 全部发现处理后自动跳转第二稿视图
- "确认落地"按钮显眼展示
- 落地性 < 95% 时确认需二次确认弹窗
- 完成后导出按钮高亮

### 5.2 架构决策记录（ADR）

|------|------|---------|------|
| ADR-001 | Tkinter 作为 GUI 框架 | PyQt / Electron / Web | MVP 阶段轻量、零额外依赖、数据本地处理；PyQt 授权成本高，Electron 体积大 |
| ADR-002 | 确定性数学引擎 vs AI 兜底 | 纯 AI 方案 | 全部计算可逐笔反算复核，金融产品必须可审计；AI 仅为交互润色可选层 |
| ADR-003 | 规则引擎兜底互动 | 强依赖大模型 | 保证离线可用率 100%，符合代账机构客户现场无网络的场景 |
| ADR-004 | Excel 作为数据交换格式 | CSV / JSON / API | 代账机构最熟悉的格式，金蝶/用友等财务软件均支持导出 Excel |
| ADR-005 | 同义词词典硬编码 + 可扩展 | 纯规则 / AI 识别 | 常见财务软件科目名有限（30-50 个同义词），硬编码可靠；留扩展接口 |
| ADR-006 | ReportLab + python-docx 生成交付物 | Pandoc / LaTeX | 精确控制 Word/PDF 格式；python-docx 成熟，ReportLab 可生成中文 PDF |
| ADR-007 | openpyxl 生成测算模型 | xlsxwriter | openpyxl 可编辑已有文件、支持公式和格式，适合生成滚动跟踪模型 |
| ADR-008 | SVG/Matplotlib 渲染图表 | ECharts / Plotly | Matplotlib 本地无需浏览器/JS 引擎，内嵌 PNG 到报告方便 |

## 七、核心引擎设计

### 7.1 财务计算引擎（finance.py）

**职责**：全部确定性数学计算，无 AI 依赖

| 功能 | 输入 | 输出 | 算法摘要 |
|------|------|------|---------|
| 增值税税负率 | 税金及附加 | 百分比 | 税金及附加 ÷ 12% × 100% ÷ 营业收入（标注"估算"） |
| 所得税税负率 | 所得税费用、营业收入 | 百分比 | 所得税费用 ÷ 营业收入 × 100% |
| 综合税负率 | 税金及附加、所得税费用 | 百分比 | (税金及附加 + 所得税费用) ÷ 营业收入 × 100% |
| 毛利率 | 营业收入、营业成本 | 百分比 | (营收 - 成本) ÷ 营收 × 100% |
| 各项费用率 | 费用、营业收入 | 百分比 | 费用 ÷ 营收 × 100% |
| 环比增长 | 本期、上期 | 百分比 | (本期 - 上期) ÷ 上期 × 100% |
| 同比增长 | 本期、同期 | 百分比 | (本期 - 同期) ÷ 同期 × 100% |
| 增值测算 | 当前值、目标值、税率 | 金额 | (目标 - 当前) × 税率 |

**设计要点**：
- 除零保护：营收为 0 时比率置 0 并标注"基数缺失"
- 精度控制：百分比保留 2 位小数，金额保留 2 位小数
- 所有计算可逐笔由原始报表反算复核

### 7.2 诊断引擎（diagnostic.py）

**职责**：基于财务数据 + 行业基准，生成结构化诊断发现

**诊断维度**：

```
1. 税负率诊断
   ├── 增值税税负率 vs 行业区间
   │   ├── 低于下限 → 真实性关注（高风险）
   │   └── 高于上限 → 提示优化空间
   └── 所得税税负率 vs 行业区间

2. 成本费用结构诊断
   ├── 毛利率 vs 行业区间
   ├── "该有没的"检测
   │   ├── 研发费用缺失或偏低
   │   ├── 福利费未达限额
   │   └── 教育经费未用足
   ├── "可有可没有/应控"检测
   │   ├── 招待费超限
   │   ├── 咨询费占比偏高
   │   └── 广告宣传费异常
   └── 费用率趋势异常

3. 真实性风险诊断
   ├── 增值税税负率异常偏低（四流合一风险）
   ├── 咨询费集中度过高
   ├── 毛利率与行业偏离过大
   └── 异常波动检测
```

**严重度规则**：

| 条件 | 严重度 | 举例 |
|------|--------|------|
| 涉及合规/税务风险 | 高 | 增值税税负率低于下限 50% |
| 影响利润超 5% | 中 | 招待费超限可调整部分 |
| 优化建议/信息提示 | 低 | 福利费未用足限额 |

### 7.3 互动引擎（interactive.py）

**职责**：管理多轮交互状态机，生成选项、处理选择、迭代方案

**状态机**：

```
IDLE → FINDING_LOOP → DRAFT2 → CONFIRMATION → FINAL
                         ↑          │
                         └──────────┘ (需求处理不完备时)
```

**选项生成策略**（规则引擎版）：
- A 选项（激进）：最大化节税，调整幅度大，落地难度高
- B 选项（平衡）：平衡节税与可行性，推荐默认
- C 选项（保守）：控制调整幅度，优先合规

**交互上下文维护**：
- 当前未决发现列表（队列）
- 历史选择记录
- 用户补充的战略意图文本
- 已计算的影响测算缓存

**第二稿生成触发条件**：
- 全部发现已处理（选择或跳过）
- 用户主动请求"生成方案"

## 九、边界场景与异常处理

### 9.1 数据边界

| 场景 | 处理方式 |
|------|---------|
| 单年数据（仅一列金额） | 按单年诊断，同比置 0 并标注"仅单年数据" |
| 科目余额表缺失 | 跳过费用细化项，基于利润表诊断，提示补充 |
| 行业未在基准库 | 回退制造业基准并提示"行业未匹配，已用制造业基准" |
| 营收为 0 | 比率置 0 并标注"基数缺失" |
| 括号负数（表示负值） | 解析器识别并转为负数 |
| 数字格式异常（千分位等） | 自动清洗数字格式 |

### 9.2 交互异常

| 场景 | 处理方式 |
|------|---------|
| 用户输入非财务内容 | 礼貌引导回"成本结构/税负优化"主题 |
| 大模型超时/失败 | 静默回退规则引擎 + 界面提示 |
| 用户主动要求提前生成方案 | 接受请求，跳转到第二稿，标注未决项 |
| 落地性 < 95% 时确认 | 二次确认弹窗提示风险 |

### 9.3 系统异常

| 场景 | 处理方式 |
|------|---------|
| 文件路径不可写导致导出失败 | 弹出错误提示 + 保留内存数据不丢失 |
| 超大文件导入 | 限制最大行数（如 5000 行），超出提示 | 
| 内存不足 | 分批处理大文件（规划） |

### 9.4 数据口径规范

- 金额单位：默认元（规划支持万元指定）
- 增值税税负率：估算值（税金及附加 ÷ 12% 反推），显著标注"估算"
- 小微/高新优惠判定：简化规则，正式申报以税务口径为准
- 所有计算精确到 2 位小数

## 十二、开发指南与协作规范

### 12.1 开发环境

| 工具 | 版本 | 说明 |
|------|------|------|
| Python | 3.11+ | 推荐 3.11 以上 |
| OS | macOS / Windows / Linux | 跨平台桌面应用 |
| 包管理 | pip + requirements.txt | 锁定版本 |
| 测试 | pytest | 配合 xvfb 做无头测试 |
| GUI 调试 | xvfb-run | 无显示器环境 |

### 12.2 快速启动

```bash
cd lirunbao
pip install -r requirements.txt
python3 main.py               # 启动桌面客户端

# 生成测试数据
python3 data/make_sample.py

# 无头测试
xvfb-run -a python3 main.py

# 运行测试
pytest tests/
```

### 12.3 代码规范

- **命名**：Pythonic snake_case，类名 PascalCase
- **类型注解**：所有公共函数须有完整类型注解
- **错误处理**：使用自定义异常类，不在 except 中静默
- **注释**：中文注释（面向国内团队）
- **日志**：使用 Python logging 模块，分级输出

### 12.4 测试策略

| 层级 | 覆盖内容 | 工具 |
|------|---------|------|
| 单元测试 | finance.py / diagnostic.py / interactive.py 核心函数 | pytest |
| 集成测试 | parser.py + models.py 数据流 | pytest |
| 端到端测试 | GUI 流程（导入→诊断→互动→导出） | pytest + xvfb |

### 12.5 合规红线

- 所有优化建议必须属于合法税务筹划范畴
- 严禁任何形式的虚开发票、隐匿收入或虚构成本表述
- 报告中固化合规声明
- 增值税税负率估算值须显著标注
