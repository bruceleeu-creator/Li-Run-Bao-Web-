# 利润宝 · 企业财税优化顾问（Web 版）

面向**财税/代账机构**的本地化智能分析工具：导入企业近三年财报，自动完成行业对标诊断与数字质检，通过多轮 AI 互动收敛出可落地的优化方案，一键产出 AI 撰写文案的**经营分析报告**（Word/PDF）、Excel 成本优化测算模型与**含月度执行计划的费用预算三表**；并配套云端**协同任务看板**，把预算方案落到逐人逐月执行、进度全员可见。

> **核心理念**：所有财税计算均为确定性数学，可逐笔由原始报表反算复核；AI 仅作可选增强，未配置时由内置规则引擎兜底——**离线也能跑通完整闭环**。客户财务数据只在本机处理，绝不外传。

## 一、产品定位与价值

### 解决什么问题

财税/代账机构在服务客户时普遍面临四个痛点：

| 痛点 | 利润宝的解法 |
|------|--------------|
| 手工分析依赖顾问个人经验，耗时长、口径不统一 | 导入即自动诊断，单客户从导入到出方案 ≤5 分钟，口径全部标准化 |
| 税负率/成本结构与行业对标缺乏系统化工具，容易遗漏 | 内置 22 个行业参考区间与判定规则，自动识别「该有没的」「可有可没有」「真实性风险」 |
| 优化建议是一次性结论，缺乏与客户战略意图的互动 | 每条发现给出 A/B/C 三个可量化选项，客户选路径、提意图，方案迭代收敛 |
| 数字提取错误难以发现，报告可信度受影响 | 独立的**数字质检引擎**双层防护（原文 OCR 字面 + 会计恒等式交叉验证），高风险数字必须人工核验后才能导出 |

### 交付物

导出页按顺序分两段（中间有分割线），两段的文案均需 DeepSeek 分析生成后填入：

- **① 经营分析报告（Word/PDF，同一份内容两种格式）**：DeepSeek 把确定性事实清单改写成"前世今生"小白版文案（先说结论 → 最以前/中间/现在 → 关键指标白话 → 将来建议 → 月度看板 → 落地清单）；跨年对照表、指标表与趋势折线图由引擎确定性生成，**禁止编造数字**，文案中出现事实清单外的数字会黄条提示人工核对（只提示、不改数）
- **② 测算模型 + 费用预算三表（Excel · 月度拆分四步向导）**：成本优化测算模型（方案概览、行动测算「当前值→目标值→变动幅度→预计节税」、可逐月勾选跟踪的执行清单）；费用预算三表升级为四步向导——DeepSeek 生成编制建议并勾选 → **生成预算第一稿**（年度底稿，不下载）→ **月度拆分问答**（AI 出题摸经营节奏，未配置 AI 用规则题库）→ **AI 定方向、引擎算金额**拆成 12 个月（每行 12 个月合计恒等于年度预算）→ 导出含「月度执行计划」Sheet 的三表；赶时间可走「跳过拆分导出旧版」逃生口

## 二、核心闭环

```
[数据导入] 拖入/选择 Excel·CSV·Word·PPT·PDF（多年审计报告自动合并）
    ↓ 自动：企业识别 + 行业推荐 + 数字质检 + 数据质量评估
[数字质检] 恒等式核对 · 小数点错位归因 · OCR 原文字面检查
    ↓
[第一轮诊断] 行业对标 → 税负率诊断 + 成本费用结构分析（初稿建议）
    ↓
[多轮互动] 每条发现给 A/B/C 三个选项（各带影响测算与落地可行性）
    ↓        可输入战略意图（如"往研发型企业转型"）
[第二稿] 环比同比 + 增值比例与幅度 + 操作细节 + 注意事项
    ↓ 双方确认 或 落地性 ≥95%
[导出·第一段] ① 经营分析报告：DeepSeek 撰写前世今生文案 → Word/PDF（同一份内容）
    ↓ ——— 分割线 ———
[导出·第二段] ② 费用编制建议 → 预算第一稿 → 月度拆分问答 → 测算模型 + 费用预算三表（含月度执行计划）
```

配套**协同任务看板**（云端独立服务，详见 3.8）：把预算与方案的执行拆成逐人逐月待办，全员同一块看板 ≤5 秒同步，老板随时监督完成度与逾期。

全程产生的**导入记录卡片**与**报告记录**保存在本机，点击即可完整载入该案例（含诊断与互动进度），随时继续未完成的分析。

## 三、功能与原理详解

### 3.1 财报导入（多格式 · 双通道解析）

- **支持格式**：`.xlsx` `.csv` `.docx` `.pptx` `.pdf`
- **两种数据形态**：
  - 单文件含三 Sheet（利润表/资产负债表/科目余额表）→ 直接解析
  - 多文件（每年一份完整审计报告）→ 按 科目+年份 自动合并成多年数据集
- **双通道解析**：
  - 文本层直读（Excel 表格 / PDF 文本层 / Word·PPT 表格）
  - 扫描件（无文本层的 PDF）→ 逐页 OCR → 整份送 DeepSeek 结构化解析 → 映射为标准数据模型（需配置 AI）
- **同义词归并**：金蝶/用友等不同财务软件的科目命名差异，通过内置同义词词典自动归一到规范科目（约 50 组映射）
- **自动识别**：选完文件自动识别企业名称与行业（AI 优先、规则回退），填入表单供确认；行业选择支持 AI 推荐

### 3.2 数字质检（独立分析层，双层防护）

因程序核心是文档数据的处理与分析，数字正确性由专门的 `core/numeric_audit.py` 引擎保障——**只提示、绝不静默改数**：

**第一层 · 扫描层（OCR 原文字面质检）**：扫描导入时采集的原文/OCR 文本，点名可疑数字字面——形近字母混入（O↔0、I/l↔1、S↔5、B↔8、Z↔2）、超长粘连数字、全角数字、千分位与小数点混用。

**第二层 · 数字层（交叉验证）**：
- **会计恒等式全式核对**：利润总额 ≈ 营收−成本−税金及附加−四费（残差≤2%营收视为正常杂项）；资产总额 = 负债+所有者权益（容差万分之一）
- **小数点错位归因**：若某科目 ×10/100/1000 后恒等式残差骤减至原 1/100，高置信判定错位并给出修正建议（如 `22,263,237,393 → 222,632,373.93`）
- **逐年跳变**（>80% 提示核对）、**业务合理性**（负营收、毛利率超区间、单项费用大于营收、利润与净利反号）

质检结果以**评分 + 等级 + 逐条发现**展示在导入页；**任一高风险发现将要求导出前人工核验关键金额**。

### 3.3 诊断引擎（行业对标）

- 基于近三年数据计算：增值税税负率（估算口径）、所得税税负率、综合税负率、毛利率、各项费用率、净利率
- 对标 22 个行业的参考区间（P25–P75 分位法 + 经验中枢法），识别：
  - **该有没的**：如研发费用缺失、福利/教育经费未用足限额
  - **可有可没有/应控**：如业务招待费超限、咨询费占比偏高
  - **真实性风险**：增值税税负率异常偏低等预警
- 可选 AI 增强：DeepSeek 补充发现与优化 A/B/C 出题（失败静默回退规则引擎）

### 3.4 A/B/C 互动与方案收敛

- 严格状态机驱动：`决策轮次 → 第二稿 → 确认 → 最终方案`，不跳项、可断点续作
- 每条发现三个选项（激进/平衡/保守），各带净影响、可行性、风险分级与分栏金额测算
- 落地性评分可解释（未决高风险项 + 暂维持选择 + 可行性加权）；**落地性 ≥95% 或用户确认**即解锁导出
- 互动进度自动快照——切换案例后再切回，从断点继续

### 3.5 案例管理（导入记录 + 报告记录）

- **每次导入自动生成记录卡片**（企业/年份/行业/文件数/时间），点击**完整载入**该案例：财务数据、诊断结果、互动进度、解锁状态、已生成的 AI 报告一并恢复，不重复整理
- **报告记录**：AI 整理与合并报告自动存档；点击报告 = 预览内容 + 载入其对应案例
- 全部记录存本机 SQLite（上限 50 条），重启不丢

### 3.6 导出交付（两段式 · 先 AI 分析后导出）

导出页按顺序分为两段，中间以分割线区隔；**分析文案都需 DeepSeek 生成后才能导出填入，数字全部由引擎确定性计算**：

**① 经营分析报告（Word/PDF）**
- 点击「生成经营分析报告」→ DeepSeek 基于事实清单撰写公司"前世今生"文案：一句话结论、先说结论、最以前/中间/现在三段故事、现在要点、指标管理判断、将来建议
- 导出 Word/PDF（同一份内容两种格式）时自动填入；艺康体小白版模板结构、跨年表、指标表与趋势折线图原样保留
- **准确性三道防线**：提示词只允许引用事实清单数字；返回后做数字白名单校验（清单外数字黄条提示、绝不静默改数）；按标题逐项合并，缺项保留规则引擎原文案（宁缺毋滥）

**② 测算模型 + 费用预算三表（Excel · 月度拆分四步向导）**
- **第 1 步 生成费用编制建议**：DeepSeek 按销售/管理/财务等科目全量编制，强制对标历史费用率、增幅匹配营收增速、金税四期合规硬顶；勾选要填入的项
- **第 2 步 生成预算第一稿**：按勾选生成年度三表底稿（**此处不下载**），页内展示摘要——年度营收 / 费用总盘子 / 费用率 / 非空费用行数 / 已填建议数
- **第 3 步 月度拆分问答**：自动出 4~6 题（收入季节性、年终奖节奏、固定费用是否平摊、投放节奏、一次性大额支出）；AI 出题失败自动回退规则题库，每题都有推荐项，一路默认也能走通
- **第 4 步 拆分与导出**：AI 依答案为每行确定**分布方向（12 个月权重）**，金额全部由确定性引擎计算并强制恒等校验——**每行 12 个月合计 = 年度预算（精确到元）、整表月度总计 = 年度总盘子**；页内透视预览带行级 ✓ 校验标识。导出的三表在原有 Sheet 之外新增「月度执行计划」Sheet（84 行 × 1~12 月矩阵，月度合计为公式可复算，差异校验列应全 0）
- **逃生口**：「跳过拆分，导出旧版年度三表」保留旧行为；第一稿/问答/拆分结果均绑定会话持久化——刷新页面或载入历史案例自动恢复到对应步骤，不重复消耗 AI

**AI 整理并导入**：整理完成即自动导入并生成导入记录卡片（整理结果存报告记录）。注意「已保存预览」仅供查看、没有原始文件——此时整理不会自动导入，页面会明确提示重新选择文件。

### 3.7 AI 能力（可选增强，离线兜底）

配置 OpenAI 兼容接口（默认 DeepSeek）后启用：扫描件 PDF 解析、AI 整理（整理完成自动导入）、跨年合并报告（逐页分段提取 + 确定性校验，防截断）、指标识别、诊断增强、月度拆分出题与权重（失败回退规则）。**未配置或调用失败时静默回退规则引擎，主流程永不阻塞**。API Key 持久化于本机 `.ai_config.json`（已 gitignore），仅内存持有。

### 3.8 协同任务看板（云端 · 已部署）

预算方案落地后的团队执行跟踪——独立云端服务（`collab_board/`），与本地端财务分析互不依赖；云端只存任务与进度数据，**请勿在任务中粘贴财报原始数字**：

- **一人一账户**：用户名+密码注册（密码加盐哈希存储，登录限流防爆破），注册自动分配专属颜色
- **老板建房拉人**：创建房间生成邀请码，员工凭码加入同一块看板；负责人可重置邀请码（旧码失效）、移除成员
- **共享看板**：待办 / 进行中 / 已完成 三列（滴答清单式），全员可创建、认领、推进、完成任务，变更 ≤5 秒全员可见；卡片左缘色条 = 创建人颜色，附成员颜色图例一眼分清「谁建的」
- **总列表视图**：单页看清整体完成度（总数 / 已完成 / 进行中 / 逾期 / 各成员完成数），支持按负责人、状态、月份筛选——「所有人同时看得见数据和完成度」的落点；房间顶部常驻完成率 / 逾期 / 今日到期
- **跟踪进度表**：独立 Excel 模板可离线批量填写后导入（逐行反馈成功/跳过与原因），看板可一键导出同结构文件供汇报留档（删两列导出专刊后可原样导回）
- **移动端**：手机浏览器响应式可用，老板随时抽查看板与完成情况
- **利润宝内嵌入口（2026-08-20）**：利润宝侧栏新增「协同看板」板块（线上版与本地版均有），点击即在页面内嵌打开本看板（iframe 指向下方地址，账号与利润宝本地互相独立，注册即可体验）

## 四、技术架构

### 分层（强制单向依赖）

```
web_backend/（FastAPI，仅 127.0.0.1:8765）      HTTP 适配层
    ↓ 只调 Pipeline 门面
core/pipeline.py  run_case_pipeline              编排层
    ↓
parser(抽取) → reconciliation(归一/勾稽) → numeric_audit(数字质检)
    → PolicySnapshot(税率/费用帽单点) → CaseBundle
    ↓
FinancialData（唯一数据真源）
    ↓ 只读
diagnostic / interactive / budget / report / action_pack
```

### 核心模块

| 模块 | 职责 |
|------|------|
| `core/parser.py` | 五格式抽取（文本层/OCR/AI 三通道），年份对齐 |
| `core/numeric_audit.py` | 数字质检引擎（双层防护 + 评分 + 修正建议） |
| `core/reconciliation.py` | 科目归一、跨年勾稽（R1/R2/R3）、贡献率合成 |
| `core/pipeline.py` + `case_manifest.py` | 统一导入管线 + 案例包（新案例零代码接入） |
| `core/industry.py` | 22 行业基准库（7 字段区间 + 预警线） |
| `core/finance.py` | 税负率/结构/环比测算（确定性数学） |
| `core/diagnostic.py` / `interactive.py` | 诊断引擎 / 互动状态机 |
| `core/ai_engine.py` | 可选大模型接口（OpenAI 兼容，禁用 thinking 防截断） |
| `core/CO_report_analysis_WB-CO-TR-20260818.py` | 经营分析报告 DeepSeek 文案层（事实清单 + 数字白名单 + 叙事合并） |
| `core/CO_monthly_split_WB-CO-TR-20260820.py` + `web_backend/CO_monthly_*` | 预算月度拆分二段式（AI 只出权重，引擎算金额 + Σ月=年恒等校验；状态机可恢复） |
| `collab_board/` | 协同任务看板独立服务（FastAPI + PostgreSQL，Docker Compose 部署 + 三页 SPA） |
| `core/report.py` / `action_pack.py` / `budget_template.py` | Word/PDF 报告 / Excel 测算模型 / 84 行预算三表 |
| `web_backend/` + `web_frontend/` | FastAPI 后端（SQLite 持久化）+ React/Vite 前端 |

### 5.8 服务器线上部署与更新指南（2026-08-20）

利润宝支持**线上版**：整站部署到腾讯云轻量服务器（OpenCloudOS 9.4 + Docker Compose），前端「协同看板」板块即嵌入的云端看板服务。线上版分两个独立服务：

| 服务 | 目录 | 容器端口 | 宿主端口 | 外网地址 | 数据 |
|------|------|---------|---------|---------|------|
| 利润宝主应用（本仓库） | `/www/wwwroot/lirunbao` | 8765 | **8082** | http://49.232.160.7:8082 | SQLite+上传+导出在 `lirunbao_workspaces` 卷，AI 配置在 `lirunbao_ai` 卷 |
| 协同任务看板 | `/www/wwwroot/collab_board` | 8080 | **8081** | http://49.232.160.7:8081 | PostgreSQL 16 卷 `board_pgdata` |

> 端口约定：8080 被宿主宝塔 nginx 占用、8081 看板、8082 主应用（均已放行）；**新增端口需在腾讯云控制台防火墙放行**（自定义 / TCP / 端口 / 0.0.0.0/0 / 允许）。

**一键更新（主应用或看板通用流程）**：

```bash
# 1) 本机准备：构建前端产物（主应用改动时；dist 已含「协同看板」板块入口）
cd web_frontend && npm run build && cd ..
# 2) 打包（只含代码，自动排除用户数据/缓存；看板则打 collab_board/）
tar --force-local -czf lirunbao.tar.gz -C <项目根> --exclude="__pycache__" --exclude="*.pyc" \
    --exclude=".mimosa" --exclude=".pytest_cache" --exclude="web_backend/workspaces" \
    Dockerfile docker-compose.yml requirements.txt web_backend core data demo_output/cases web_frontend/dist
# 3) 上传并解压（SSH 密钥：~/.ssh/lrb_board，root@49.232.160.7）
scp -i ~/.ssh/lrb_board lirunbao.tar.gz root@49.232.160.7:/tmp/
ssh -i ~/.ssh/lrb_board root@49.232.160.7 'tar -xzf /tmp/lirunbao.tar.gz -C /www/wwwroot/lirunbao'
# 4) 重建并滚动重启（秒级中断；长构建必须 nohup 分离，见注意事项）
ssh -i ~/.ssh/lrb_board root@49.232.160.7 \
  'cd /www/wwwroot/lirunbao && nohup docker compose up -d --build > /tmp/lirunbao_build.log 2>&1 < /dev/null &'
# 5) 验证：外网 health 200 + 页面可开
curl http://49.232.160.7:8082/api/health   # 主应用 → {"status":"ok","bind":"0.0.0.0"}
curl http://49.232.160.7:8081/api/health   # 看板 → {"status":"ok","db":true,"env":"prod"}
```

**看板更新**：打包 `collab_board/` 到 `/www/wwwroot/collab_board`，`docker compose up -d --build`（同流程，镜像名 `collab_board-app`）。**回滚**：`docker images` 找上一镜像标签 → `docker compose up -d` 指回旧标签（或 `git revert` 后重建）。**数据备份**：每日 03:00 crontab 自动 `pg_dump`（看板，留 7 份 `/www/backup/board-db-*.dump`）；主应用 SQLite 卷建议定期 `docker run --rm -v lirunbao_workspaces:/data -v /www/backup:/backup alpine tar -czf /backup/lirunbao-data-$(date +%F).tar.gz /data`。

**线上注意事项（踩坑实录）**：

- **腾讯云 SSH 网关会掐断长会话**：超过几分钟的构建/大任务必须 `nohup ... > /tmp/xxx.log 2>&1 &` 分离执行，再轮询日志；前台跑必被断连
- **apt/pip 必须走腾讯云镜像**（Dockerfile 已内置）：服务器直连 deb.debian.org / PyPI 极慢（apt 曾卡 10+ 分钟）；`pip` 已指定 `mirrors.cloud.tencent.com/pypi`，`apt` 已 sed 替换 sources
- **端口被占**：`docker compose up` 报 `address already in use` 时旧容器会卡 `Restarting`，先 `docker rm -f <容器名>` 再 up；容器名可能带 hash 前缀，用 `docker ps` 确认
- **改代码后镜像层缓存**：只改应用代码（COPY 层）时重建约 1 分钟；改 requirements 才重跑 pip（约 2 分钟，镜像源）
- **容器重启策略**：db/app 均 `unless-stopped`，服务器重启自动拉起
- **安全**：云端不存放任何财报原始数据（财报只在本机处理）；看板只存任务/进度；`.env` 与 AI 配置均 chmod 600 且不入镜像

**自动更新（GitHub Actions，2026-08-24）**：仓库已配置 CI/CD——推送到 main 后自动跑六分组检查（守护门禁 / 模块A 全量 pytest / 模块A e2e / 模块B 板端测试+e2e / 双 Docker 镜像构建），全绿后按上面同一 SOP 自动打包上线（按改动路径自动判定只更主应用 / 只更看板 / 两者；纯文档提交不碰服务器）。三个 secret（`LRB_SSH_HOST`/`LRB_SSH_USER`/`LRB_SSH_KEY`）已于 2026-08-24 配置完成，deploy 链路就绪；也可在 Actions 页手动触发 Deploy 工作流选择目标。本地一键命令：`bash scripts/一键推送部署_WB-CO-TR-20260824.sh "feat: xxx"`（守护 → 提交 → 推送，内置代理绕过，之后交给 CI）。细节见 AGENTS.md「GitHub Actions CI/CD」节。

## 六、数据安全与合规

- **数据不出本机**：后端仅绑定 `127.0.0.1`；不收集统计、不回传信息；AI 为可选且密钥仅存本机
- **私有仓库分发**：不开源，仅授权内部财税/代账同事使用，不得二次分发
- **合法筹划边界**：所有优化建议限于合法税务筹划范畴（研发费用加计扣除、限额内据实扣除、业务模式优化等），严禁任何违规筹划表述；增值税税负率为估算口径（基于税金及附加反推），UI/报告/Excel 均显著标注；具体执行前建议与主管税务机关或注册税务师确认
- **数字不静默修改**：质检只提示与建议，任何修正必须人工对照原文确认
